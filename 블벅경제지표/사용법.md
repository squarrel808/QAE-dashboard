# 블룸버그 WECO 경제지표 — 사용법

이 폴더에 블룸버그에서 내보낸 엑셀을 떨궈 넣으면 경제지표 캘린더가 갱신된다.

---

## 1. 블룸버그에서 내보내기 (터미널에서 2번)

WECO 화면에서 **두 번** 내보낸다. 한 번은 지표, 한 번은 연설·이벤트다.

**① 지표**
1. `WECO <GO>`
2. 기간 설정 — 보통 지난 한 달 ~ 앞으로 한 달
3. 국가 선택 (US / DE / JP / UK / CA / FR / IT / EZ / RU ... 보고 싶은 만큼)
4. 화면 종류를 **Economic Releases (지표)** 로 둔 상태에서
5. `Output → Export to Excel`

**② 연설·이벤트**
1. 같은 WECO 화면에서 종류를 **Central Bank / Speeches·Events** 로 바꾼다
2. 다시 `Output → Export to Excel`

두 파일을 **이 폴더(`블벅경제지표`)에 그대로 저장**한다. 끝.

> 내려받은 파일 이름은 `32253597_20260902_050757_eco.xlsx` 처럼 생겼다.

---

## 2. 파일 이름 / 개수 규칙

- **파일명은 아무래도 상관없다.** 번호가 매번 바뀌어도 된다. `_eco.xlsx` 로 끝나기만 하면 된다.
- **최근 2주 안에 넣은 파일을 전부 합쳐서 쓴다** (파일 수정시각 기준, 최대 6개).
  같은 일정(날짜·시각·국가·이벤트)이 여러 파일에 있으면 **최신 파일 값**을 쓴다.
  2주보다 오래된 파일은 자동으로 빠지니 굳이 지우지 않아도 된다.
- **1개만 새로 넣어도 된다.** 새 파일이 덮는 기간은 새 값으로 갱신되고, 그 밖의
  기간은 이전 세트가 그대로 남는다. (예: 이번 주치만 다시 내보내 떨궈 넣기)
- **어느 쪽이 지표이고 어느 쪽이 연설인지 신경 쓰지 않아도 된다.** 파일 안의 내용
  (컨센서스가 채워진 비율, 중요도 값)으로 알아서 갈라낸다.
- 지표 파일에도 들어 있고 연설·이벤트 파일에도 들어 있는 일정(예: BOC 금리결정)은
  **숫자가 있는 지표 쪽 한 줄만** 남는다.
- ⚠️ 기간을 통째로 새로 잡고 싶으면(예: 9월 한 달) 지표·연설 **2개를 같이** 내보내
  넣어라. 그래야 옛 파일 값이 남지 않는다.
- ⚠️ 엑셀에서 파일을 **열어 둔 채로 두지 마라.** 임시파일(`~$...`)이 생겨도 무시하도록
  되어 있지만, 파일이 잠겨 있으면 읽기가 실패한다.

---

## 3. 표시되는 것 / 안 되는 것

- **지표는 컨센서스(Survey)가 있는 것만 나온다.** 시장 예상치가 없는 지표는
  서프라이즈를 볼 수 없으니 애초에 빼 버린다. 블룸버그가 `--` 로 비워둔 것도 전부 제외다.
  - 지금 파일 기준: 지표 1,197행 중 **495행**만 남는다.
- **연설·이벤트는 전부 나온다.** (컨센서스가 없는 게 정상이므로)
- **국가는 파일에 있는 그대로 전부 나온다.** 임의로 빼지 않는다.
  더 많은 나라를 보고 싶으면 1번 단계에서 WECO 국가 선택을 늘려서 다시 내보내면 된다.
- 숫자는 블룸버그 원본 그대로다. `0.011` 은 1.1%를 뜻하지만 원본대로 `0.011` 로 보여준다.
- `9/23/2026-9/30/2026` 처럼 발표일이 기간으로만 잡힌 지표는 **시작일**에 놓고
  시간 칸은 비워 둔다.

## 4. 갱신하기

새 엑셀을 넣은 다음(2개 세트든, 이번 주치 1개든), 이 폴더에서:

```
python load_weco.py
```

정상이면 이런 식으로 나온다 — **어떤 파일을 골랐는지 여기서 확인하면 된다.**

```
[source] C:\Users\infomax\Documents\python\QAE\블벅경제지표
  * 32253597_20260902_193634_eco.xlsx  (수정 2026-09-03 08:45)  -> 지표(ind)  173행 중 63행 사용, ...
  * 32253597_20260902_050757_eco.xlsx  (수정 2026-09-02 18:17)  -> 지표(ind)  1197행 중 432행 사용, ..., 최신 파일에 있어 건너뜀 63행
  * 32253597_20260902_050846_eco.xlsx  (수정 2026-09-02 18:17)  -> 연설·이벤트(evt)  57행 중 52행 사용
[rows] 547
[kind] 지표 495 / 연설·이벤트 52
[기간] 2026-08-03 ~ 2026-09-17
```

`최신 파일에 있어 건너뜀` = 더 최신 파일이 같은 일정을 이미 갖고 있어 옛 파일 값을
쓰지 않은 행이다. 정상이다.

여기까지 확인됐으면 대시보드 HTML 생성 스크립트를 돌린다.

## 5. 문제가 생기면

| 증상 | 볼 곳 |
|---|---|
| `... 에 해당하는 파일이 없습니다` | 파일 이름이 `_eco.xlsx` 로 끝나는지, 이 폴더에 있는지 |
| 고른 파일이 내가 방금 넣은 게 아니다 | 실행 결과 맨 위 `*` 줄들의 **수정 시각**을 본다. 맨 위가 가장 최신이어야 한다 |
| 옛날 값이 그대로 남아 있다 | 그 일정이 새 파일에 없어서 이전 파일 값이 살아남은 것이다. 기간을 다시 잡아 2개를 새로 내보내면 된다 |
| 지표/연설이 뒤바뀌었다 | 실행 결과의 `판별근거:` 줄을 본다. `survey %` 와 `rel평균` 이 높은 쪽이 지표다. 두 파일을 같은 종류로 내보낸 건 아닌지 확인 |
| 있어야 할 지표가 안 보인다 | 십중팔구 **컨센서스가 없는 지표**다. 원본 엑셀에서 그 행의 Survey 칸이 `--` 인지 확인 |
| 국기가 🌐 로 나온다 | 처음 보는 블룸버그 국가코드다. `load_weco.py` 위쪽 `FLAG` / `DISP` 에 그 코드를 한 줄 추가하면 된다 |
| 행 수가 0 이다 | 엑셀을 열어 헤더가 `Date Time / Country Code / ... / Relevance / Ticker` 인지 확인. 블룸버그 내보내기 형식이 바뀌었을 수 있다 |
| 콘솔에 글자가 깨진다 | 무시해도 된다. 데이터에는 영향 없다 |

## 6. 파일 구성

| 파일 | 역할 |
|---|---|
| `load_weco.py` | 엑셀 2개 → 캘린더 데이터. `load_rows()` 하나만 쓰면 된다 |
| `*_eco.xlsx` | 블룸버그에서 내려받은 원본. 최근 2주(최대 6개)를 합쳐서 쓴다 |
| `weco_global.xlsx` | 구버전(국가별 시트) 원본. 지금은 쓰지 않는다 |
