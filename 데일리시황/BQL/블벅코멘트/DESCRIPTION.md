# Bloomberg 코멘트 반복 정리 규칙

이 문서는 사용자가 Bloomberg에서 복사한 일별·수일치 시황 코멘트를 매번 같은 방식으로 정리하기 위한 영구 작업 설명서다.

## 1. 기본 요청 해석

사용자가 Bloomberg 코멘트 텍스트를 주면서 “정리해줘”, “같이 넣어줘”, “전에 한 포맷으로 만들어줘”라고 하면 다음을 기본값으로 적용한다.

- 결과물 언어: 한국어
- 기본 기간: 최근 3개 실제 시장 스냅샷을 하나의 흐름으로 정리
- 기본 보고서: 유럽·미국·일본 섹터·산업 로테이션 **5D**, S&P 500 AI 밸류체인 **5D**, 그리고 현재 Bloomberg 입력에 팩터 데이터가 있을 때 별도 팩터·테마 HTML
- 디자인: 흰 배경, 네이비 헤더, 상승 파란색, 하락 빨간색, 간격이 좁은 기관투자자용 표
- 핵심 구조: `날짜별 전개 → 공통 매크로 → 팩터·테마 → 지역별 차이 → 섹터 → 특징주 → 다음 확인 변수`
- BQL 종목 표: 섹터별 5D 상위 3개, 하위 3개. 상위 종목도 절대수익률이 음수일 수 있으므로 `상승/하락`이 아니라 `상위/하위`로 적고, 화면에는 티커를 표시하지 않는다.
- Bloomberg 원문에 `Stocks in Focus`, `Key Stock Movers` 또는 이에 준하는 종목표가 있으면, 날짜·시장·섹터별 별도 표를 만들어 원문에 적힌 모든 종목의 수익률 표현, 확인 촉매, broader read-through를 한국어로 전부 옮긴다. 같은 날짜에 중복 인용된 행만 합치고 다른 날짜의 동일 종목은 남긴다.
- 종목표 번역과 별개로 Bloomberg 원문의 **섹터 전체 해설, 11개 섹터별 동인, 섹터 간 비교, 기간별 로테이션, 지역 간 전염, 당시 관찰 변수**를 모두 찾아 날짜·지역별 독립 섹션으로 옮긴다. 짧은 BQL 섹터 카드 코멘트는 원문 해설 번역을 대체하지 않는다.
- 긴 원문을 날짜별로 그대로 반복하지 않고, 전일의 원인이 다음 날 어떤 가격반응으로 이어졌는지 연결한다.

## 2. 데이터 출처 원칙

### Bloomberg 코멘트만 정리하는 경우

- 날짜별 시황, 거시 변수, 팩터, 테마, 지수 및 종목 설명은 **사용자가 준 Bloomberg 텍스트만** 사용한다.
- 별도 웹 검색은 하지 않는다.
- `reported`, `estimated`, `no confirmed catalyst`는 확정 사실처럼 바꾸지 않는다.
- 자료 작성 시점 이후 예정된 이벤트는 “당시 예정”으로 표시한다.

### BQL 섹터 보고서와 결합하는 경우

- 섹터 수익률, BM 수익률, 비중, 상승 종목 비율, 종목 순위는 최신 BQL 원자료에서 계산한다.
- Bloomberg 텍스트는 가격 움직임의 원인, 팩터 변화, 지역 간 전염 경로를 설명하는 용도로만 사용한다.
- Bloomberg 표와 BQL 계산치가 다르면 숫자를 섞거나 평균내지 않는다. 본문 숫자는 BQL 계산치를 우선하고, 차이는 방법론 주석으로 남긴다.
- 원문 총평에 수치가 포함되면 출처 날짜·가격일·기간·ETF/바스켓/지수 프록시·total return/price return·확정/추정/보도치 여부를 붙여 **BQL 정량표와 물리적으로 분리**한다. 서로 다른 날짜의 원문 5D를 하나의 연속된 수익률 시계열로 연결하지 않는다.
- 원문 작성시각보다 미래인 종가, 원문 자체가 비표준이라고 밝힌 구간, 본문과 표의 부호 불일치, 상충하는 전망은 검증 전까지 핵심 수치에서 제외하고 원문 품질 주석에 남긴다.
- 추가 웹 검색은 사용자가 요청했거나 종목별 촉매 검증이 필요한 경우에만 한다. 추가했다면 링크와 `HIGH / MEDIUM / LOW` 확신도를 붙인다.

### 정량 표와 코멘트 결합 방식 — 고정 규칙

최종 보고서는 반드시 다음 두 단계로 만든다.

1. 기존 정량 생성 코드가 표, 수익률, 비중, 상승 종목 비율, 순위, 상·하위 종목을 전부 계산해 **base HTML/JSON**을 만든다.
2. 별도 commentary JSON의 문장과 출처만 base HTML의 코멘트 슬롯에 결합한다.

코멘트 단계에서는 표 행을 만들거나 수익률·비중·순위·종목 선정을 다시 계산하지 않는다. 날짜별 전용 스크립트에 표 HTML과 숫자를 복사하거나 하드코딩하지 않는다. 정량 값이나 방법론이 틀렸다면 코멘트로 덮어쓰지 말고 정량 생성 코드를 먼저 고친 뒤 base를 다시 만든다. 코멘트가 없거나 결합에 실패해도 검증된 base 표는 그대로 남아야 한다.

공통 결합기는 다음 파일이다.

`BQL\Theme\Material\attach_commentary.py`

```powershell
python -X utf8 attach_commentary.py --base-html <정량표.html> --commentary-json <코멘트.json> --output <최종_코멘터리.html>
```

commentary JSON에는 `global`, `markets`, `sectors`, `stages`, `stocks` 아래의 문장·날짜·출처·URL·확신도만 둔다. `returns`, `rank`, `weight`, `breadth`, `benchmark`, `tables`, `rows` 같은 정량 필드는 금지한다. `target.report`, `target.asOf`, `target.primary`는 base HTML과 일치해야 하며, 필요하면 `target.baseSha256`으로 정확한 base 파일도 고정한다.

## 3. 5D 계산 기준

- 5D는 실제 거래일 종가 6개를 사용한 5개 수익률 구간이다.
- 섹터 및 합성 BM은 구간 시작일 종목별 시가총액으로 가중한다.
- 종목별 현지통화 가격수익률을 사용하며 배당은 제외한다.
- STOXX Europe 600은 원천 시가총액 통화가 혼재할 수 있으므로 비중과 가중수익률을 근사치로 표시한다.
- 현재 구성종목으로 과거 시작일을 계산했다면 생존편향 가능성을 적는다.
- 동일가중 BM을 공식 지수수익률처럼 표시하지 않는다.

15. 방법론 및 주의사항

Bloomberg 일간 종목과 BQL 5D 상·하위 종목은 선정 기준과 기간이 다르므로 같은 행에 억지로 합치거나 일간 촉매를 5D 전체의 원인처럼 덮어쓰지 않는다. ETF·바스켓은 종목이 아니라 프록시로 표시한다.

AI 보고서는 같은 디자인으로 별도 파일을 만들고 `Core+Adjacent / Core` 보기, 12개 밸류체인 전 기간 성과표, 밸류체인별 특징주, 접이식 `분류종목·근거` 전체 표를 포함한다. AI 집계는 섹터 보고서와 달리 `Σ(Price×Shares)/ΣShares`를 사용하므로 두 방법론을 섞지 않는다.

팩터·테마 Bloomberg 블록이 있으면 짧은 요약으로 끝내지 않고 별도 페이지를 만든다. 팩터별·테마별 5D/1M 그래프, 강약 순위, 지역 확인, 테마 리더·래거드, 핵심 로테이션을 옮긴다. 복사본에 원래 이미지나 완전한 일별 시계열이 없으면 제공된 종점 값만 그래프로 재배치하고 중간 경로는 만들지 않는다.

## 5. 시황을 읽는 기본 프레임

### 날짜별 전개

- 1일 차: 최초 충격 또는 반등 원인
- 2일 차: 전일 재료의 강화·반전 여부
- 3일 차: 다른 지역으로의 전염과 지수 구성 차이

### 자산 간 연결

- 유가 → 기대인플레이션 → 중앙은행 경로 → 국채금리 → 주식 할인율
- 금리 → 성장주·리츠·유틸리티·은행 내부 차별화
- AI 뉴스 → 반도체·서버·전력 인프라와 소프트웨어·사이버보안 간 차별화
- 환율 → 일본 수출주, 유럽 외화매출, 캐리트레이드 영향

### 반드시 구분할 것

- 시장 전체 매도인지 일부 대형주·산업의 집중 매도인지
- AI 테마 종료인지 AI 가치사슬 내부 로테이션인지
- 방어주 상승인지 단순 낙폭 방어인지
- 금융의 NII 수혜와 대출·IB·트레이딩 둔화 위험
- 에너지주의 이익 수혜와 고유가가 전체 시장에 주는 할인율 부담

## 6. 데이터 품질 점검

최종 출력 전에 다음을 확인한다.

- 기준일과 실제 마지막 거래일이 일치하는가
- 미국·유럽·아시아 시장의 시차와 휴장일을 구분했는가
- 1D 값 0.00%가 실제 보합인지, 시장 개장 전 스냅샷인지
- `price return`, `total return`, `open-to-close`, `close-to-close`가 섞이지 않았는가
- ETF 프록시와 구성종목 직접 계산치를 동일한 값처럼 비교하지 않았는가
- 서로 다른 통화·지수 방법론을 단순 순위화하지 않았는가
- 본문과 표의 숫자가 서로 모순되지 않는가
- 비정상적으로 큰 수익률과 `estimated` 값을 검산했는가
- 뉴스와 가격이 동시에 발생했다는 이유만으로 인과관계를 확정하지 않았는가

문제가 있는 값은 본문 핵심 수치에서 제외하고 데이터 품질 주석에 남긴다.

## 8. 이번 완성본의 출처 구분

이번 `유럽_미국_일본_섹터_산업_5D_코멘터리_20260914.html`은 다음처럼 만들었다.

- 상단 3일 시황 타임라인과 팩터·지역 해석: 사용자가 준 Bloomberg 텍스트
- 섹터 5D 수익률·BM·비중·상승 종목 비율·상하위 종목: 최신 BQL 원자료
- 종목별 촉매 링크: 앞선 작업에서 별도로 확인한 공개 뉴스와 기업 공시 포함
- Bloomberg 섹터 전체 해설: 9/11 및 9/14~15 원문을 날짜별 독립 섹션으로 추가. 미국 11개 섹터별 동인, 유럽·일본 지수별 업종 해설, 섹터 간·지역 간 비교, 당시 관찰 변수, 원문 품질 경고를 포함한다. 이는 BQL 5D 표와 별도다.

따라서 **상단에 새로 추가한 3일 시황은 사용자가 준 텍스트 기반이 맞지만, 보고서 전체가 그 텍스트만으로 작성된 것은 아니다.**

## 9. 반복 실행 시 최종 체크리스트

- [ ] 마지막 유효 거래일 확인
- [ ] 3개 스냅샷의 실제 날짜 확인
- [ ] 5D 종가 6개와 가격 커버리지 확인
- [ ] 시작일 시가총액가중 재계산
- [ ] 원문 숫자와 BQL 숫자를 혼합하지 않음
- [ ] BQL 특징주는 `상위·하위` 각 3개로 표시하고, 음수인 상위 종목을 상승으로 오표기하지 않음
- [ ] Bloomberg 종목표가 있으면 날짜 안 중복만 제거한 모든 행을 한국어로 옮기고, 일간 수익률·촉매·시장 해석을 5D 표와 분리함
- [ ] Bloomberg 섹터 총평·개별 섹터 동인·섹터 간 비교·기간별 로테이션·지역 간 비교·당시 관찰 변수를 날짜별로 전부 대조해 별도 원문 섹션에 옮김
- [ ] 원문 숫자의 가격일/작성일/기간/산식/확실성을 표시하고 작성 시각과 모순되거나 비표준인 값은 성과표에 쓰지 않음
- [ ] 유럽·미국·일본 산업그룹 전체 표가 시작일 시총가중 수익률로 계산됨
- [ ] 상단 비교표 마지막의 시장별 5D 상승 종목 비율이 각 시장 탭 KPI 및 유효 구성종목 계산치와 일치함
- [ ] AI 12개 밸류체인과 Core/Adjacent 분류가 최신 run과 일치함
- [ ] AI 종목 분류와 포함 근거 토글이 있음
- [ ] 현재 Bloomberg 팩터 데이터가 있으면 별도 팩터·테마 페이지와 테마별 그래프가 있음
- [ ] 팩터·테마의 1D 미반영 0값, ETF 이상치, long-only 프록시 한계를 표시함
- [ ] 직접 촉매와 추정 코멘트를 구분
- [ ] 한글 UTF-8, 빈 표, `NaN`, `undefined` 점검
- [ ] 1D 보고서가 아니라 5D 전용인지 확인
- [ ] 날짜별 output 폴더에 저장
- [ ] 정량 표는 기존 생성 코드의 base HTML/JSON 한 벌만 사용하고 코멘트 단계에서 재계산하지 않음
- [ ] commentary JSON에 표 숫자·순위·비중·상하위 종목 배열을 중복 저장하지 않음
- [ ] 코멘트의 `report / asOf / primary`가 base HTML과 일치함

## 10. 고정 호출 문구

사용자가 `데일리 시황 작성해줘`라고 하면 최신 4개 원자료를 갱신한 뒤 위의 섹터·산업 보고서와 AI 밸류체인 보고서를 **항상 한 쌍으로** 만든다. 이 동작은 Codex 스킬 `qae-daily-market-brief`에 저장되어 있다. `데일리 표 업데이트해줘`는 서술 보고서 없이 표만 갱신하는 별도 요청이다.
