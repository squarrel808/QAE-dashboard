## 실행과 결과

`데일리시황\데일리_표_업데이트.cmd`를 실행한다. 결과 입구는 `데일리시황\표_업데이트\index.html`이다.

기본은 **1D 표 + 1D·5D·1M·3M·6M 숫자**다. 주간이 필요하면 `--period 5D`, 두 표를 함께 갱신하려면 `--period both`를 사용한다. 입력을 확인만 하려면 `--check`를 사용한다.

- 기존 계산 모듈과 밸류체인·GICS 분류, 표 구성을 재사용한다. 기존 사업 설명·분류 근거는 유지한다.
- AI·섹터는 표와 숫자만 갱신한다. 신규 서술형 보고서, Word/PDF 보고서 작성이나 뉴스 조사는 포함하지 않는다.
- 주가 기준일은 한국 기준 전일까지의 마지막 실제 거래일이다. 원본 수정시각을 거래일로 쓰지 않는다. 시장별 기준일 불일치·가격 범위 부족은 오류로 표시한다.
- ECFC 표는 이번 원본의 전체 수록 기간을 읽는다. 별도 `Consensus Builder\history`의 누적 이력과 기존 장기 대시보드는 변경하지 않는다. 이번 화면에 원본 밖의 과거 관측을 채워 넣지 않는다.
- 각 실행은 `표_업데이트\runs\요청시각`에 숫자 JSON, HTML 표, 원본 이름·해시·수정시각과 검증 기록을 저장한다. 전체 단계가 성공해야 최신 입구를 바꾼다.
- 로컬 파일 갱신이다. 외부 게시, git push, 사이트 배포, 스케줄 등록은 이 실행에 포함되지 않는다.

## 섹터·AI 보고서의 표와 코멘트 결합

섹터·AI 서술 보고서는 기존 숫자 갱신 결과를 다시 계산하지 않는다.

1. `update_daily_tables.py`와 유지관리 중인 정량 모듈이 실행별 JSON과 base HTML을 완성한다.
2. 별도 commentary JSON에는 문장, 날짜, 출처, URL, 확신도만 저장한다.
3. `BQL\Theme\Material\attach_commentary.py`가 base HTML의 지정 슬롯에 코멘트만 넣어 날짜별 최종 HTML을 만든다.

날짜별 코멘터리 스크립트에서 표 HTML, 수익률, 비중, 상승 종목 비율, 순위, 상·하위 종목 선정을 다시 만들거나 하드코딩하지 않는다. 정량 방법론을 바꿔야 하면 정량 생성기를 먼저 수정하고 base를 다시 만든다. 코멘트가 없거나 결합이 실패하면 검증된 base HTML을 그대로 보존한다.

## WECO 코멘트와 해석

2026-09-17 사용자 정정: WECO 새 파일 유무나 일부 IB 수집 실패는 해석·게시 전체의 중단 사유가 아니다. 현재 사용 가능한 최신 숫자와 안정적으로 확보된 원문으로 계속 갱신한다. 새 숫자가 없으면 기존 숫자를 유지하고 신규 근거만 반영하며, 수치 기준일과 오늘 해석·게시일을 분리한다. 실패 하우스·미검토 원문은 명시하고 완료로 기록하지 않는다. 검증 실패나 동시 수정으로 안전한 게시가 불가능할 때는 정상 게시본을 보존한다.

1. **요청 시점에 원본 H열의 실제값이 있는 항목**을 기본 표시한다. 미래 날짜 항목은 실제값 검토 대상에서 제외한다. 원본의 시각은 그대로 보존하며, H열의 값이 작업 시점에 관측됐다는 의미로 취급한다. 실제값 미수록은 0이나 추정값으로 채우지 않는다.
2. **정확한 국가·지표·대상 기간에 대해 원문을 확인한 IB 코멘트**가 저장되어 있으면 연결한다. 발표 전 전망과 사후 반응을 구별한다. 수치 전망은 단위까지 일치해야 한다.
3. 직접 코멘트가 없으면 지표명·동의어와 국가/지역을 결합해 IB 원문 DB를 먼저 검색한다. PMI는 `PMI / purchasing managers / ISM`과 제조업·서비스·종합 구분을 함께 쓰는 식으로 지표별 검색어를 적용한다. 검색 결과는 **미검토 원문 후보**이며 IB 코멘트로 확정하지 않는다.
4. 기존 growth/inflation 뷰는 지표 검색을 대체할 수 없다. 지표 상세에서는 접힌 `상위 거시 배경`으로만 사용한다. 다만 **별도 `IB 거시 맥락 뷰` 페이지는 항상 유지**한다. 지표 전용 화면으로 바꾸면서 기존 국가별 Growth / Inflation / 통화정책 비교를 없애지 않는다. **현재 기본 갱신은 새 해석을 작성하지 않는다.**
5. 사용자가 해석을 요청하면 원문 후보의 전체 페이지를 우선 검토한다. 정확한 지표·국가/지역·대상 기간에 대한 직접 언급이면 코멘트를 작성하고, 발표 전 전망과 발표 후 반응을 구별한다. 직접 언급이 없을 때만 기존 IB 견해를 보조 근거로 AI 추론을 작성하며 실제 IB 발언과 구분한다. 근거 없는 하우스에는 해석을 만들어 넣지 않는다.
6. `WECO\review_queue.json`에 전체 실제값 수록 항목, 신규 실제값 / 변경된 수치 / 변동 없음 상태, 지표·지역별 IB 원문 후보를 보관한다. 실제·예상·종전·수정값 변경은 재검토 대상이다. 사용자가 AI 해석을 시킬지 직접 확인할지 결정한다.
7. 해석 요청의 결과는 대화 답변만으로 끝내지 않고 `authored_commentary.json`과 기존 INDEX가 가리키는 WECO에 반영한다. 화면은 수치 → 짧은 핵심 요약·지표 해석 → 다음 확인점 → IB별 한국어 요약·AI 비교 코멘트 순서다. 긴 원문을 본문처럼 붙이지 않는다. 원문 인용·검색 후보는 접고 출처 제목·발행일·페이지는 추적할 수 있게 남긴다.
8. `authored_commentary.json`은 정확한 지표 식별과 검토 당시 실제·예상·종전·수정·단위·배율·통화 스냅샷이 맞는 경우에만 재사용한다. 불일치한 요약은 현재 해석으로 표시하지 않고 재검토 대상으로 남긴다. 발표 전 전망/발표 후 반응/다른 기간·세부지표의 관련 분석을 구별한다. `reviewed_comments.json`의 기존 연결과 견해 이력도 보존한다.

## IB 거시 맥락 뷰와 날짜

- `WECO/index.html`(지표별 요약·IB 코멘트)과 `WECO/macro_views.html`(국가별 거시 맥락)을 같은 실행 폴더에서 함께 생성하고 기존 `표_업데이트/index.html`·실행별 INDEX·두 화면 사이의 이동 링크를 유지한다. 작업용 복사본/`dist`를 별도 메인으로 안내하지 않는다.
- 거시 뷰는 IB별 Growth / Inflation / 통화정책을 핵심 전망·전제·리스크/확인 질문·이전 견해와의 변화·자료일·출처로 정리한다. 이전 이력과 긴 원문은 펼쳐 볼 수 있게 보존한다. 확보되지 않은 하우스·쟁점은 공백으로 남긴다.
- `build_macro_views.py`는 `living_ib.sqlite3`와 `reviewed_comments.json`의 보강 견해를 읽는다. 기존 지역(호주·글로벌 포함)을 캘린더 국가 목록에 맞춰 누락시키지 않고, 유로존 뷰를 독일·프랑스·이탈리아의 독립 하우스뷰로 복제하지 않는다. 에너지 위험과 시장금리 전망은 각각 물가 결정/정책금리 결정과 구분한다.
- HTML 재생성·PDF 검색 DB 갱신은 새 견해 검토가 아니다. 생성일, 지표 코멘트 검토일, 거시 견해 자료일, 검색 DB 최신 보고서일을 따로 표시한다. 모든 AI 작성물은 사용자 검토 전 초안이다.
- 기본 숫자 갱신과 저장 내용 재표시는 LLM API를 호출하지 않는다. 사용자가 요청한 새 해석은 이 앱의 모델 작업이며 사용량을 쓴다. 거시 뷰 갱신은 새 보고서를 검토하여 고유 ID/이전 ID로 추가하는 별도 절차다. 지표 AI 추론으로 living 상태를 덮어쓰지 않는다.

기존 IB 뷰와 직접 코멘트를 숫자 갱신만으로 새 전망으로 바꾸지 않는다. 지표 검색 후보가 있다는 사실도 직접 코멘트가 확보됐다는 뜻이 아니다. 새 PDF를 단순히 넣은 것만으로 새 직접 코멘트가 생성되지 않는다. 앞서 작성한 고정 해석 템플릿을 다시 보여주는 기능은 새 AI 분석과 다르다.

예전 `run_ai_report*`, `run_sector_report*`, `run_final*` 파일은 과거 수동 실행 경로다. 앞으로 **데일리 요청의 기본 실행은 이 문서의 표 업데이트 경로**를 따른다.
