## 새 지표 해석 — 직접 요청 또는 07:20 예약

아침 실행 파일은 **새 AI 해석을 작성하지 않는다.** 로컬 숫자 읽기·FTS5 검색·저장된 요약/견해 표시에는 LLM API 호출이 없다. 사용자가 이 앱에 새 요약·해석을 요청하면 모델이 필요한 원문을 읽고 작성하므로 그 대화 작업에는 모델 사용량이 든다. 해석을 대화창에만 남기지 않고 저장 파일과 위 대시보드에 반영한다.

사용자가 해석을 요청하면 **지표 우선 방식**으로 처리한다. 먼저 `지표명·동의어 + 국가/지역 + 발표 전후 시점 + IB`를 조합해 원문을 검색한다. 예를 들어 PMI는 `PMI`, `purchasing managers`, `ISM`에 제조업·서비스·종합 구분과 Japan·Euro area 같은 지역어를 함께 검색한다. CPI, 고용, 소매판매, 산업생산 등도 각 지표의 전용 동의어를 사용한다.

아침 갱신은 이 검색을 토큰 없이 수행해 각 지표·IB별 **미검토 원문 후보**를 `dashboard_data.json`과 `review_queue.json`에 넣는다. 후보는 관련 페이지를 찾기 위한 자료이며 곧바로 IB 코멘트로 표시하지 않는다. 사용자가 해석을 요청하면 후보 페이지 전체를 읽고, 해당 지표·기간에 대한 직접 언급이 있으면 코멘트를 요약한다. 직접 언급이 없을 때만 기존 growth/inflation 견해를 보조 배경으로 사용하며, 지표 코멘트처럼 대신 표시하지 않는다. 보조 배경으로 추론할 경우 `AI 해석 초안`으로 명시하고, 근거가 없으면 미확보로 둔다.

예: “오늘 실제값이 들어온 지표를 IB별로 해석해줘”, “신규·수정된 미국 지표만 해석해줘”. 직접 확인할 때는 숫자와 기존 IB 근거만 읽으면 된다.

새 PDF를 폴더에 넣거나 검색 DB를 갱신하는 것만으로 새로운 직접 코멘트가 생기지는 않는다. 앞서 작성한 고정 해석 문구를 다시 표시하는 옵션도 새 보고서를 읽는 AI 분석과는 다르다.

저장한 지표 요약은 `authored_commentary.json`에서 재사용한다. 국가·발표일/시각·지표명·대상 기간을 맞추고 실제·예상·종전·수정값과 단위/배율/통화가 검토 당시와 모두 일치해야 한다. 달라지면 기존 요약을 현재 해석으로 노출하지 않고 재검토 상태로 남긴다. 원문 요약과 AI의 비교 판단은 구분한다.

거시 뷰를 최신화해 달라는 요청은 별도의 원문 검토 작업이다. 동일 IB·국가·쟁점을 이전 보고서와 대조하고 새 견해 ID와 이전 ID를 연결한다. 지표 AI 코멘트를 IB의 새 하우스뷰로 승격하거나 기존 견해 이력을 덮어쓰지 않는다.

실패하면 오류를 확인하고 해당 실행 폴더의 `update.log`를 확인한다. 전체 단계가 성공해야 최신 결과 입구가 갱신되므로, 기존 화면이 열린다고 이번 갱신이 성공한 것은 아니다. 화면의 요청 시점과 데이터 기준일을 함께 확인한다.

이 문서의 실행 파일은 로컬 표 갱신용이다. 기존 `전체업데이트.bat`의 수집·게시 흐름과 별개이며, 외부 업로드·git push·사이트 배포를 실행하지 않는다.
