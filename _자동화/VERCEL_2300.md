# 매일 23:00 Vercel 배포

한국시간 매일 23:00에 기존 BAT의 실행 본체인 `run_qae.py /nightly /dataonly`를 실행한다.
예약은 Python을 직접 실행해 종료 상태를 추적하며, 수동 실행용 `run_vercel_2300.bat`도 같은 실행 흐름을 호출한다.
기존 오전 07:00 예약은 유지한다. 컴퓨터가 켜져 있고 infomax 사용자가 로그인되어 있어야 한다.
오전 예약에도 `/nohouseviews`를 추가해 리포트 요약문을 별도로 재분석하지 않는다.
놓친 예약은 다음 실행 가능 시점에 실행하고, 실행이 겹치면 중복 실행하지 않는다.

1. 바탕화면 `보따리/YYMMDD/*요약*.docx`를 읽어 Report 목록을 갱신한다.
   사용자의 2026-09-21 요청대로 만들어진 문서의 요약을 재사용한다. 추가 요약/분석 API는 호출하지 않는다.
   `/nohouseviews`는 별도 Claude 분석을 생략하고 기존 하우스뷰를 유지한다. 기본 화면은 최신 보고서 목록이며 두 자료의 최신 날짜를 각각 표시한다.
2. 웹 JSON과 저장된 대시보드 HTML을 동기화한다. Haver 로그인/PDF 재수집/전체 원천데이터 수집은 수행하지 않는다.
3. 최신 요약 누락·7일 초과 지연·하우스뷰 API 실패·JSON 오류가 있으면 전송을 중단한다.
4. `macro_hub/public/data`, `macro_hub/public/embeds`만 커밋하고 전송한다. 이전 push 실패도 재시도한다.
5. 실제 사이트의 실행 식별자, 배포 파일 해시, Report 화면을 최대 15분 확인한다. 확인 실패는 성공으로 표시하지 않는다.

전체 단계 로그: `logs/qae_YYYYMMDD.log`. 전송 성공과 Vercel 사이트 확인은 `logs/run_steps.csv`의 별도 단계다.
야간 실행은 기존 아침 데이터 수집을 대체하지 않는다. 원천 대시보드가 오래되면 해당 탭 데이터도 오래된 상태다.

실행 계획만 확인: `run_vercel_2300.bat /dryrun`
로컬 갱신만 확인: `run_vercel_2300.bat /nogit`

2026-09-21 확인: 바탕화면 보따리에 9월 21일 요약이 존재했다. 원인은 잘못된 폴더가 아니라
요약 생성 전 07:00 배포 순서와 최근 파이프라인 중단이었다. 마지막 기존 배포 Report는 9월 2일이었다.


## 2026-11-10 변경
