그대로 복원한 고정 보관본으로, 정기 갱신 및 sync 스크립트가 덮어쓰지 않는다.
이번 복원은 음수 제약만 제거하는 실험이 아니다. II·III의 기존 제약을 유지한다.

## 보관 위치

- `2026-10-29_pre_cfna/source_data_and_results.zip`: 이전 계산 코드·설정·게시 화면,
  당시 원자료 및 변경 전 계산 결과. 로컬 ZIP이며 무결성을 검증했다.
- `legacy_20261029.json`: 이전 커밋, 게시 파일 해시, ZIP 해시와 원자료 해시.
- `outputs/pca_cfna_comparison/before`: 변경 직전의 계산 코드·결과 원본.
- Git 보관 태그 `pca-before-cfnai-2026-10-29`: 이전 게시 코드·화면의 영구 기준점.

이전 게시본의 PCA I와 비교 보고서의 “기존” 결과는 구분한다. 비교 보고서는
방법론 차이를 분리하려고 동일한 원자료로 예전 코드를 다시 계산한 결과이다.
ZIP에는 마지막 게시본과 그 재계산 결과를 모두 별도 경로에 남겼다.

## 나중에 기존 방식으로 다시 바꿀 때

전체 저장소를 과거로 되돌리지 않는다. 다른 대시보드 변경을 보존한다.
위 Git 태그 또는 ZIP의 `previous_commit`에서 PCA 계산·표시·검증 코드만
선택적으로 복원한다. I의 원래 Momentum 산식도 함께 복원할지 먼저 확인한다.
당시 수치를 복원하려면 게시 스냅샷을 사용하고, 최신 데이터로 예전 방법을
계산하려면 예전 엔진을 최신 원자료에 실행한 뒤 지표·가중치·결측·부호를 검증한다.
PCA I의 JSON과 II·III 게시 스냅샷, 자동 갱신 경로와 검증 스크립트까지
같은 방법론으로 맞춘 뒤 배포한다. 현재 버전은 별도 보관하고 덮어쓰지 않는다.

`preserve_legacy.py`는 이 날짜의 원자료 해시가 일치할 때만 실행하는 보관 도구다.
일일 갱신 과정에 넣지 않는다. `macro_hub` build는 보관 게시 파일을 검증만 한다.
